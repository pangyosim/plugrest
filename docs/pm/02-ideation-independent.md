# 독립 아이디에이션 — Top 3 (2026-11-03)

입력: `docs/research/01-contest-brief.md`, `02-pleos-api-inventory.md`만 참고. 다른 pm 문서 미열람.

## 공통 전제 (선별 필터)
- **차속 신호 없음** → 주행/정차 판단은 Gear(P/R/N/D) + Brake + CarUxRestrictions. 속도 기반 기능(과속, 연비 코칭)은 전부 배제.
- Virtual Console로 **직접 흔들 수 있는 신호**만 핵심 루프에 사용: Gear, Brake%, 조향각, 방향지시, Odometer, SOC/충전포트/전류, Door/트렁크, Window, **Seat Occupancy**, HVAC, 실내등/앰비언트, 와이퍼, Telltale, 하이패스.
- 모바일 포팅 금지 → "차량이 아니면 **감지할 수 없거나 실행할 수 없는** 일"만 채택. 폰으로 대체 가능하면 탈락.
- 2차 PT는 오프라인 실기 시연 → 3분 안에 콘솔 조작 → 차량 반응이 눈에 보여야 함.

## 아이디어 A. 뒷자리 (가칭) — 반려동물·아이 뒷좌석 케어 모드

**한 줄**: 운전자가 내렸는데 뒷좌석에 누군가 남아 있으면, 차가 알아서 "돌봄 모드"로 전환해 온도·창문·조명을 유지하고 배터리로 버틸 수 있는 시간을 알려준다.

**Pain point**
- 반려동물 동반 외출 시 잠깐 편의점/식당 들르는 10~30분이 가장 불안. 여름 차내 온도는 10분에 7°C 상승. 아이 뒷좌석 방치 사고도 매년 반복.
- 기존 ROA(후석 승객 알림)는 "경고만" 하고 끝난다. **행동(HVAC 유지, 창문 틈, 남은 시간 계산)** 은 아무도 안 해줌. 폰 앱은 차내 온도도, 시트 착좌도, 공조 제어도 불가능 → 차량 전용.

**핵심 루프**
1. 감지: `Gear==P` + 운전석 `occupancy==false` + 운전석 Door 열림 + 뒷좌석 `occupancy==true` → "뒷자리에 동승자가 남아 있어요. 케어 모드 켤까요?" (큰 버튼 2개 + TTS)
2. 켜기: HVAC 목표온도 22°C·풍량 2단, 창문 전좌석 10% 하강(설정값), 앰비언트 라이트를 '케어 색(민트)'으로 전환, 도어 잠금.
3. 지속: SOC·HVAC 소비 추정으로 **"유지 가능 시간 약 N시간"** 을 큰 숫자로 표시. 외부에서 보이도록 앱 영역에 "반려동물 케어 중, 보호자 곧 복귀" 문구.
4. 감시: SOC가 설정 하한(기본 20%) 밑으로 → 풍량 절전 + 창문 추가 5% + 차량 알림. 뒷좌석 도어가 열리거나 occupancy가 false가 되면 자동 종료.
5. 복귀: 운전석 occupancy true → "케어 모드 종료, 23분 유지, 배터리 3% 사용" 리포트. 이게 다음 번 "유지 가능 시간" 추정 보정값이 됨.

**SDK 사용 (도메인 → 패턴)**
- Vehicle.Seat: `checkSeatCapabilities` → `get(occupancy, 전좌석)` → `register(onSeatUpdated)` — 핵심 트리거
- Vehicle.DrivingMode/Gear: `get(gear)`, `register` — P 판정
- Vehicle.Door: `get(열림/잠금)`, `set(lock)`
- Vehicle.HVAC(CONTROL_CAR_CLIMATE): `set(temp, fanSpeed, ac, recirculation)`
- Vehicle.Window(CONTROL_CAR_WINDOWS): `set(position=10%)`
- Vehicle.Light(CONTROL_CAR_LIGHTS): `set(ambient color/brightness)`
- Vehicle.EvBattery: `get(SOC, capacity)`, `register(onEvBatteryUpdated)` — 유지 시간 추정·하한 경보
- TextToSpeech: 모드 진입/종료 안내. FusedLocation: 복귀 시 "주차 위치" 보조(선택)
- AAOS CarUxRestrictions: 모드 설정 화면은 P에서만 노출

**Virtual Console 데모 스크립트 (약 2분 30초)**
1. 초기: Gear D, 운전석·뒷좌석 Occupancy ON. 앱은 "주행 중" 최소 UI.
2. Gear → P, 운전석 Occupancy OFF, 운전석 Door → Open → 앱이 TTS와 함께 "케어 모드?" 카드 팝업 (심사위원에게 가장 큰 임팩트 포인트).
3. "켜기" 터치 → 콘솔의 HVAC 온도가 22로, 창문 위치가 10%로, 앰비언트 색이 바뀌는 것을 **콘솔 화면에서 역확인** (set이 실제로 들어갔다는 증거).
4. SOC 슬라이더 60 → 18로 내림 → 앱이 "배터리 부족, 절전 전환" + 풍량 1단, 창문 15%로 바뀜. 차량 알림 1건 발생.
5. 뒷좌석 Occupancy OFF (또는 운전석 ON) → 자동 종료 + 요약 리포트.

**사업성**
- 타깃: 반려동물 양육 가구 ~600만 가구(국내), 그중 EV/신차 구매층 + 영유아 가정. 1차 타깃은 "반려동물과 자주 이동하는 EV 오너".
- MAU 로직: 트리거가 **자동**(뒷좌석 착좌 + 하차)이라 사용자가 앱을 '열' 필요가 없음 → 설치 = 활성. 펫 동반 외출 주 2~3회 → 월 10회 세션.
- Retention: 매 세션 끝 리포트("오늘 23분 안전 케어") → 누적 기록이 자산이 됨. 펫 프로필·사진은 가볍게.
- 확장: 펫 보험·펫 동반 가능 장소(NaviHelper 목적지 추천), 아이 카시트 모드, 렌터카/카셰어링 B2B 옵션.

**가장 큰 리스크**: 보호자는 차 밖에 있는데 앱은 차 안에 있다. 하한 경보를 보호자에게 전달하려면 푸시 백엔드가 필요(SDK 범위 밖). MVP는 "출발 시 유지 가능 시간 고지 + 차량 자율 대응"으로 한정하고, 푸시는 로드맵으로. 또 하나: 시동 OFF 상태에서 HVAC 유지가 실차 정책상 허용되는지 — 에뮬레이터에선 문제없으나 PT에서 질문 들어올 것. "유틸리티 모드/Stay 모드 존재 차종 한정" 으로 답 준비.

## 아이디어 B. 하차 30초 — 매 운행 종료 자동 점검·정리

**한 줄**: 주차하고 내리는 순간, 차가 창문·라이트·트렁크·타이어·배터리를 한 번에 스캔해서 "내일 출근 괜찮은지"까지 한 화면 + 한 번의 터치로 정리해준다.

**Pain point**
- 내리고 나서 "창문 닫았나? 라이트 껐나? 충전 꽂아야 하나?" 되돌아오는 경험은 전원 있음. 차는 각각 따로 경고음만 낸다(창문 따로, 라이트 따로). **묶어서 한 번에 해결**하는 UI가 없음.
- EV 오너의 "내일 아침 충전량 불안"은 출근 전날 밤의 고정 스트레스. 폰은 창문·라이트 상태를 모르고 닫을 수도 없음 → 차량 전용.

**핵심 루프**
1. 트리거: `Gear==P` + Brake 해제 + 운전석 Door 열림(또는 운전석 occupancy false).
2. 스캔(병렬 get): Window 4개 위치, Light(외부등/실내등), Door/트렁크, Tire TPMS 텔테일, EvBattery SOC + 충전 포트 상태, Odometer 트립.
3. 판단: 내일 첫 목적지(NaviHelper 최근 목적지/즐겨찾기 "회사") 거리 × 효율(EvBattery 누적 효율) vs 현재 SOC → "내일 왕복 가능 / 충전 필요".
4. 한 화면: 녹색 체크 N개 + 빨간 항목만 크게. "모두 정리" 버튼 하나 → Window close, 실내등 off, Door lock 순차 set. TTS로 1문장 요약("창문 닫고 잠갔어요. 배터리 34%, 내일 출근엔 충분해요").
5. 종료: 트립 거리·효율 기록 → 주간 "출퇴근 리포트" 카드(열어보는 건 선택).

**SDK 사용**
- Vehicle.Window: `get(position)`, `set(close)` / Vehicle.Light: `get/set(interior, exterior)` / Vehicle.Door: `get(open/lock, trunk)`, `set(lock)`
- Vehicle.Tire: `get(TPMS)` / Vehicle.Safety: `get(telltales)`
- Vehicle.EvBattery: `get(SOC, 충전포트, 누적 효율)` / Vehicle.Odometer: `get(trip)`
- Vehicle.DrivingMode/Gear + Brake + Seat(occupancy): 트리거
- NaviHelper: 최근 목적지·즐겨찾기 조회(내일 거리), 충전소 목적지 설정(충전 필요 시 원터치)
- TextToSpeech: 요약 1문장. 오디오 포커스 짧게.

**Virtual Console 데모 스크립트 (약 2분)**
1. 콘솔 사전 세팅: 운전석 Window 40%, 외부등 ON, 트렁크 Open, TPMS 텔테일 ON, SOC 22%, 충전포트 미연결.
2. Gear D → P, Brake 100 → 0, 운전석 Door Open → 앱 전면 전환, 빨간 항목 5개 + "내일 출근(32km 왕복) 충전 필요" 배지.
3. "모두 정리" 터치 → 콘솔에서 Window 0%, 외부등 OFF, Door Lock으로 바뀌는 것 확인. 트렁크·TPMS는 "직접 확인하세요"로 남음(제어 불가 항목 구분 = 성숙도 어필).
4. "충전소 안내" 터치 → NaviHelper 목적지 설정 → 내비 화면 호출.
5. SOC를 70으로 올리고 다시 D→P 하차 → 이번엔 전부 녹색, TTS 1문장 후 자동 종료 (매일 쓰는 가벼움 강조).

**사업성**
- 타깃: 출퇴근 EV 오너 전부. 주제 예시 "출퇴근/충전/주차" 세 개를 동시에 치는 보편 기능.
- MAU 로직: **운행 종료마다** 자동 실행 → 운전 횟수 = 세션. 1일 2회 → 월 40회+. 사용자 행동 비용 0.
- Retention: 가치가 매일 반복되고 실패(창문 열어둠)의 비용이 커서 삭제 유인이 낮음. 다만 "앱을 능동적으로 연다"는 지표는 낮을 것 → 리텐션 지표를 '세션 자동 실행률'로 정의해야 함.
- 확장: 법인 차량 반납 점검(렌터카·카셰어), 가족 공유차 "마지막 사용자 리포트", 보험사 도난·파손 예방 제휴.

**가장 큰 리스크**: 창의성 점수. 각 요소는 차량에 이미 조각조각 있음("라이트 켜짐 경고음"). 차별점은 "묶음 + 내일 예측 + 원터치 실행"이라 PT에서 '편의 기능 모음' 으로 보이면 평범해짐. 또 OEM이 OTA로 흡수하기 가장 쉬운 아이디어.

## 아이디어 C. 깜빡이 코치 — 속도 없이 되는 운전 습관 피드백

**한 줄**: 방향지시등 없이 핸들을 꺾는 순간, 급브레이크를 밟는 순간을 차가 직접 세고, 운행이 끝나면 초보·자녀 운전자에게 "오늘의 3가지"만 알려준다.

**Pain point**
- 한국 운전자 최대 불만 1위가 "깜빡이 안 켜는 차". 정작 본인은 자기가 안 켠 줄 모른다. 폰 UBI 앱은 GPS·가속도계라 **방향지시등 조작·브레이크 답력** 을 전혀 모름 → 차량 전용 데이터.
- 자녀에게 차 빌려준 부모, 초보 운전자, 법인 차량 관리자는 "어떻게 운전했는지"를 알 방법이 없다.

**핵심 루프**
1. 운행 시작: `Gear P→D` 에서 세션 시작. 주행 중 UI는 숫자 하나(오늘 점수)만, CarUxRestrictions로 상호작용 차단.
2. 이벤트 감지(리스너 기반, 폴링 없음):
   - 조향각이 임계(예 ±25°) 넘는 동안 TurnSignal이 한 번도 켜지지 않음 → "신호 없는 조향" 1회
   - Brake 페달 % 가 짧은 시간에 70%+ → "급제동" 1회
   - 벨트 텔테일 ON 상태로 D 진입 → "벨트 미착용 출발"
   - 비오는데(와이퍼 ON) 외부등 OFF → "우천 등화 미점등"
3. 운행 중 피드백: 이벤트 직후 짧은 톤 1개 + 앰비언트 라이트 0.5초 주황 깜빡 (시선 안 뺏음). 설정에서 끌 수 있음.
4. 운행 종료(`Gear→P`): Odometer 트립 거리당 이벤트 수로 점수 → 카드 1장 "오늘의 3가지" + TTS 1문장.
5. 주간 리포트 + 공유 코드(부모/법인 관리자에게 리포트 보내기, 2단계).

**SDK 사용**
- Vehicle.TurnSignal: `register(onTurnSignalUpdated)` / 조향각: Vehicle.DrivingMode 또는 Brake 도메인의 조향각 값 `register` (인벤토리상 Virtual Console에 조향각 존재, 소속 도메인은 구현 시 확인)
- Vehicle.Brake: `register(onBrakeUpdated)` 페달 %
- Vehicle.Safety: `get/register(telltale: 벨트, ABS)` / Vehicle.Wiper + Vehicle.Light(외부등): `get`
- Vehicle.Odometer: 트립 거리 → 분모 / Vehicle.DrivingMode/Gear: 세션 경계
- Vehicle.Light(CONTROL_CAR_LIGHTS): 앰비언트 피드백 / TextToSpeech: 종료 요약
- AAOS CarUxRestrictions: 주행 중 리포트 화면 잠금

**Virtual Console 데모 스크립트 (약 2분 30초)**
1. Gear P→D, 벨트 텔테일 ON 상태 → 즉시 "벨트" 이벤트 1 (시작부터 반응).
2. 조향각을 0→+40° 로 돌림(방향지시 OFF) → 앰비언트 주황 깜빡 + 카운트 +1. 이어서 방향지시 L ON 후 조향각 -40° → 카운트 안 올라감(정상 판별 증명).
3. Brake 0→90→0 빠르게 → "급제동" +1. 20→40→0 천천히 → 미집계.
4. 와이퍼 ON + 외부등 OFF → "우천 등화" 경고. 외부등 ON → 해제.
5. Odometer 트립 +8km 입력 후 Gear→P → 리포트 카드: 점수 + "오늘의 3가지" + TTS.

**사업성**
- 타깃: 1차 초보·자녀 운전자(면허 3년 이내 약 300만) + 부모, 2차 법인·렌터카 플릿 관리자, 3차 보험사(UBI).
- MAU 로직: 운행마다 자동 세션. 능동 열람은 주 1회 리포트. 리포트를 '보내는' 사람(부모·관리자)이 존재해 **두 명이 묶인 리텐션** 구조.
- Retention: 점수는 지루해지기 쉬움 → 상대평가 없이 "지난주 나 vs 이번주 나"만. 깜빡이 카운트는 사회적 체면 요소라 이야깃거리가 됨.
- 수익: 보험사 안전운전 할인 데이터 제휴(차량 네이티브 신호라 폰 UBI보다 신뢰도 높음), 플릿 B2B SaaS.

**가장 큰 리스크**: **차속이 없다.** 급제동·조향 판별이 저속 주차 조작과 구분이 안 된다(주차장에서 핸들 꺾는 건 깜빡이 안 켬). 완화: Gear R 중 제외, 트립 거리 변화율로 저속 구간 추정, 연속 조향(주차 패턴) 필터. 그래도 오탐이 눈에 띄면 신뢰가 깨지고 PT에서 바로 지적당함. 두 번째 리스크는 개인정보(운전 기록) 약관·처리방침 필수.

## 채점 (5점 척도)

| | 차량특화성 | 창의성 | 기술활용성 | 사업성 | 합계 |
|---|---|---|---|---|---|
| **A. 뒷자리 (펫·키즈 케어)** | 5 | 4 | 5 | 4 | **18** |
| C. 깜빡이 코치 | 5 | 4 | 4 | 4 | 17 |
| B. 하차 30초 | 5 | 3 | 5 | 3 | 16 |

근거 메모
- 차량특화성: 셋 다 폰으로 불가능. 동점 5.
- 창의성: A는 "경고 → 자율 대응 + 유지 시간"으로 ROA/Dog Mode 대비 한 단계 앞. C는 '깜빡이'라는 한국적 pain point 명확. B는 묶음 편의라 독창성 약함.
- 기술활용성: A·B는 get+set 도메인 7~8개가 **핵심 기능 자체**. C는 read 위주(set은 앰비언트뿐).
- 사업성: C가 보험·플릿 수익 경로가 가장 선명하지만 오탐 리스크가 데이터 가치를 깎음. A는 명확한 니치(펫 EV 오너) + 자동 트리거. B는 사용 빈도는 최고지만 돈 될 길이 흐림.

## #1 선정: A. 뒷자리 (펫·키즈 뒷좌석 케어 모드)

이유 세 가지.
1. **주최 주제 두 개(반려동물 동승, 가족 이동)를 정면으로 치고**, 심사위원이 3초 안에 "아, 이건 차에서만 되는 거네"를 이해한다. 설명이 필요 없는 아이디어가 PT에서 이긴다.
2. **데모가 가장 극적이다.** Seat Occupancy + Gear + Door 세 신호 조합으로 '차가 상황을 알아챈' 장면을 연출할 수 있고, 그 뒤 HVAC·창문·앰비언트가 콘솔에서 실제로 바뀌는 걸 역확인시킬 수 있다. set 계열 도메인을 가장 많이, 가장 의미 있게 쓴다 → 기술활용성 만점 근거.
3. **리스크가 '설명 가능한' 리스크다.** 푸시 알림 부재와 시동 OFF HVAC 정책은 로드맵/차종 한정으로 답할 수 있다. 반면 C의 오탐은 시연 중 터지면 수습이 안 되고, B는 "이미 있는 기능 아닌가요" 한 마디에 무너진다.

보조 전략: B의 '하차 시 창문·라이트 점검'은 A의 케어 모드 종료 리포트에 체크리스트 1줄로 흡수 가능. C는 별도 앱으로 두되 A가 떨어질 경우 플랜 B.

마감(11/15)까지 12일. A는 도메인 8개 get/set + 리스너 + TTS + P 전용 UI로 범위가 명확하고, 외부 백엔드 없이 APK 하나로 끝난다. 실기 PT(12/3~4)에 가장 안전하게 도달하는 선택.
