## 1. 앱 한 줄 소개

전기차 충전 대기 시간을 원탭으로 휴식으로 바꾸고, **배터리 목표 또는 출발 시각**에 맞춰 조명을 서서히 밝혀 차가 운전자를 깨운 뒤 원래 상태로 되돌려 주는 Pleos Connect 앱.

## 2. 기획 배경

- **충전은 길다.** 서울 급속 충전기의 하루치 이용 기록을 실측한 연구에서 급속 충전 1회 평균은 47.2분이었다[7]. 소비자 설문(컨슈머인사이트, 2021)에서도 급속 충전에 평균 47분이 걸린다고 답했지만, 바라는 시간은 30분 이내였고, 구매자 불편 1순위는 "긴 충전 시간"이었다[8].
- **그 시간을 차 안에서 보내는 사람이 있다.** 유럽 BEV 운전자 조사(Gilbarco Veeder-Root, 2025)에서 급속 충전 중 4명 중 1명이 차 안에서 기다린다고 답했다(25%)[10]. 국내 조사는 없다.
- 지금 그 사람들은 시트를 손으로 젖히고, 조명과 공조를 따로 맞추고, 휴대폰 타이머를 따로 건다. 언제 끝날지 몰라 화면을 계속 확인하고, 완료를 놓치면 충전기를 계속 차지해 다음 사람이 기다린다.
- **휴식 자체는 이미 시작됐다. 비어 있는 건 끝내는 과정이다.** 기아 EV3는 "충전 중 차 안에서 휴식"을 공식 마케팅하고 있고, 릴렉션 시트(원터치 리클라인)와 목표 SOC 자동 충전 중지는 이미 순정 기능이다. 그러나 공개 자료로 확인할 수 있는 범위에서는, 시트·조명·공조를 한 번에 휴식 상태로 바꾸고 목표 도달 시점에 맞춰 깨운 뒤 원래대로 되돌리는 시나리오는 보이지 않는다(2026-11 기준, 오너스 매뉴얼 미확인).
- **릴렉션 시트·무드램프·유틸리티 모드가 만드는 것은 쉬는 '환경'이고, 충전쉼표가 설계하는 것은 '시간과 기상'이다.** 배터리 목표나 출발 시각에 맞춰 조명을 서서히 밝혀 깨우고, 원래대로 되돌리고, 하차까지 점검하는 '끝내기'를 차가 알아서 해 준다.
- 이 불편은 휴대폰 앱으로 풀 수 없다. 시트 각도·착좌, 앰비언트 조명, 공조, SOC 변화는 차량 안에서만 읽고 제어할 수 있다.
- **1차 대상**: 충전 중에도 인포테인먼트가 켜져 있고 공조·시트 제어가 허용되는 차종(유틸리티 모드 지원 차종)이다. 차량 전원 상태 신호는 SDK에 없다. 그래서 제어가 거부되면 "이 차량에서는 지원되지 않음"으로 표시하고, 가능한 항목만으로 시나리오를 줄여 실행한다.

## 3. 앱 주요 기능 및 차량 특화 요소

| 기능 | 해결하는 문제 | 차량 특화 요소 (모바일로 불가능한 이유) |
|---|---|---|
| **충전 감지 → 휴식 모드 버튼** | 충전을 시작한 뒤 따로 설정해야 하는 번거로움 | 충전 포트 연결에 더해 배터리 잔량 상승이나 충전 스위치 ON을 확인해 실제 충전 중인지 판단하고, 충전 중일 때만 "휴식 모드 시작"을 켠다. 폰은 이 신호를 받을 수 없다 |
| **원탭 휴식 모드** | 시트·조명·공조를 하나씩 수동 조작 | 리클라인 전에 뒷좌석 착좌를 먼저 확인하고, 운전석 뒤에 사람이 있으면 절반만 젖힌다. 앰비언트 조명을 어둡고 따뜻한 색으로 바꾸고, 실내등을 끄고, 공조를 22°C·풍량 1단·외기 유입으로 맞춘다(장시간 재순환으로 인한 CO₂ 상승 방지). 통풍 시트는 선택(기본 OFF) |
| **출발 시각 모드** | 충전은 배터리 기준으로 끝나지만, 사람은 "30분 뒤에는 출발해야 한다"처럼 시각 기준으로 움직임 | 목표를 배터리(80/90%) 대신 출발 시각(15/30/45분 후)으로 고를 수 있다. 화면에는 "출발까지 N분"을 크게, "출발 시 약 N%"를 보조로 보여 준다. 출발 시 배터리는 학습값이나 실측 충전 속도로만 계산하고, 근거가 없으면 표시하지 않는다. 출발 시각 전에 충전이 먼저 끝나면(포트 분리, 100% 도달, 충전 멈춤) 시각을 기다리지 않고 "충전이 끝났어요. 배터리 N%"로 바로 깨워, 충전기를 오래 차지하지 않는다. 차량의 충전 한도 설정은 SOC 기준이라 '시각에 맞춘 휴식'이라는 개념이 없고, SOC를 실시간으로 읽어 출발 시 배터리를 예측하는 일은 차 안에서만 할 수 있다 |
| **SOC → 남은 분** | 언제 끝나는지 몰라 화면과 타이머를 계속 확인함 | 처음 3분은 "계산 중"으로 두고, 이후 최근 5분 SOC 상승률로 남은 시간을 5분 단위로 보여 준다. 80% 이후 충전 속도가 느려지는 구간은 따로 보정한다. 목표(80/90%)는 앱이 SOC를 감시해 도달을 판단하며, **사용자의 차량 충전 한도 설정은 건드리지 않는다** |
| **충전 속도 학습** | 매번 처음 3분은 "계산 중"이라 언제 끝날지 바로 알 수 없음 | 이 차량의 실제 SOC 상승 속도(80% 이하·초과 구간 따로)를 세션마다 기기에 쌓아, 두 번째 충전부터 "지난 충전 n회 기준 약 N분"을 바로 보여 주고 실측이 잡히면 실측으로 바꾼다. 차량 신호로 학습하는 차량 맞춤 값이라 폰 앱은 만들 수 없다 |
| **선라이즈 기상** | 깨울 때 갑작스러운 알람 소리에 놀람 | 종료 3분 전부터 앰비언트 조명 밝기를 30초 간격으로 조금씩 올려(따뜻한 색 유지) 조명을 천천히 밝혀 깨운 뒤 음성으로 안내한다. 처음부터 꺼 둔 조명은 켜지 않고, 공조 풍량(1단→2단)은 충전 중일 때만 올린다. 무드램프는 색·밝기를 고르는 설정이고, 조명과 공조를 시간 축으로 움직이는 기상 순서는 없다. 조명을 지원하지 않는 차량은 공조만, 둘 다 지원하지 않으면 생략한다 |
| **도달 깨움 + 자동 복원** | 잠들어 목표 도달이나 출발 시각을 놓치고 충전기를 계속 차지함 | "목표 80%에 도달했습니다"(출발 시각 모드는 "출발 시각입니다. 배터리 N%")라고 음성으로 깨우고, **10초 카운트다운**(화면에 "취소" 버튼)을 거쳐 시트·조명·공조를 시작 전 상태로 되돌린다. 취소하면 지금 상태 그대로 둔다. 완료 화면에서 확인하지 않으면 30초 간격으로 최대 3회 다시 알린 뒤 스스로 종료한다. 시트가 움직이는 중에 화면을 터치하면 즉시 멈춘다 |
| **하차 체크 카드** | 창문·실내등을 켜 둔 채 하차, 뒷좌석 확인 누락 | 창문 위치·실내등 상태·좌석 착좌를 읽어 "조수석 창문 열림", "뒷좌석에 사람이 있어요"처럼 한 줄로 안내한다 |

- **주행 안전**: 충전쉼표는 정차 전용 앱이다. Distraction Optimized(DO)를 선언하지 않아서 주행 중에는 플랫폼이 앱 사용을 막고, 앱에는 주행 중 화면이 없다. 그 위에 안전장치를 하나 더 둔다. AAOS `CarUxRestrictionsManager`가 주행 제한을 알리거나 기어가 P를 벗어나면 **모든 제어를 즉시 멈추고, 시트 복원도 하지 않는다**. 복원은 정차 상태에서만 실행한다. 시트를 되돌리지 못한 채 주행했다면, 다시 정차했을 때 음성으로 한 번 알리고 "되돌리기 / 그대로"를 묻는다. 정차 중 브레이크를 밟으면 출발 의도로 보고 시트를 먼저 되돌린다.
- **창의성**: 휴식 자세와 충전 중지는 각각 이미 있는 기능이다. 새로운 점은 **충전 시작부터 출발까지를 시간 축 위의 하나의 상태 흐름으로 정의**했다는 데 있다. 진입은 원탭이고, 배터리 목표나 출발 시각을 기준으로 남은 시간 안내, 선라이즈 기상, 복원, 하차 점검이 차량 신호로 자동 처리된다.

## 4. 주요 사용 시나리오

**대표 시나리오 — 고속도로 휴게소 급속 충전, 30분 뒤 출발 (평일 퇴근길, 운전자 1인)**
1. 휴게소 급속 충전기에 차를 연결하고 P단에 둔다. SOC는 50%다. 앱이 충전 중임을 확인하고 "휴식 모드 시작" 버튼과 목표 선택 줄(배터리 80/90% · 출발 15/30/45분 후)을 켠다.
2. 운전자는 30분 뒤 다시 출발해야 해서 "출발 30분 후"를 고르고 시작한다. 뒷좌석이 비어 있는지 확인한 뒤 등받이가 뒤로 젖혀지고 실내가 어두운 주황빛으로 바뀐다. 음성으로 "출발까지 30분, 편히 쉬세요. 시간에 맞춰 깨워 드릴게요"라고 안내한다.
3. 화면에는 "출발까지 30분"이 크게 보이고, 그 아래에 "출발 시 약 N%"가 보인다. 지난 충전 기록이 있으면 바로, 없으면 실제 충전 속도를 확인한 뒤 표시한다. 화면 밝기는 최소로 낮아지고, 운전자는 눈을 붙인다.
4. 출발 3분 전, 앰비언트 조명이 천천히 밝아지고 바람이 조금 세진다. 화면 상태줄에는 "곧 깨워 드릴게요 · 조명을 천천히 밝히는 중"이 뜬다.
5. 출발 시각이 되면 음성으로 "출발 시각입니다. 배터리 76%. 10초 후 시트를 원래대로 되돌립니다"(배터리 값은 예시)라고 안내한다. 10초 뒤 시트·조명·공조가 충전 전 상태로 돌아간다.
6. 하차 체크 카드가 "조수석 창문 열림"을 알려 준다. 운전자는 창문을 닫고 커넥터를 뽑은 뒤 바로 출발한다.

**변형**
- **충전이 먼저 끝나면**: 출발 시각 전에 포트가 분리되거나 100%에 이르거나 충전이 멈추면, 시각을 기다리지 않고 "충전이 끝났어요. 배터리 N%"로 안내한 뒤 같은 깨움·복원 흐름으로 넘어간다. 충전기 점유를 늘리지 않기 위해서다.
- **배터리 목표 모드**: 80/90%를 고르면 같은 흐름이 SOC 기준으로 움직인다. 처음 3분은 "계산 중", 이후 실측 남은 시간을 보여 주고, 남은 시간이 3분 이하가 되면 선라이즈를 시작한다(추정이 없으면 목표 도달 시 바로 안내). 음성은 "목표 80%에 도달했습니다"다.
- 운전자가 충전을 먼저 끝내거나 "종료"를 누르면 정차 상태에서 바로 복원한다.
- 다른 앱으로 넘어가도 휴식 모드는 계속 유지되고, 목표에 도달하면 깨움과 복원이 실행된다.
- 충전 포트를 분리했거나 휴식 시작 후 2시간이 지나면, 10초 예고 후 원래 상태로 되돌리고 종료한다. 젖혀진 시트를 그대로 남기지 않기 위해서다.

## 5. 개발 계획

**개발 범위 (2차 PT까지 MVP)**
- 화면 3개(대기 / 휴식 / 완료)와 충전 감지 → 휴식 모드 → 깨움·복원 → 하차 체크 플로우. 주행 중 화면은 만들지 않는다.
- 휴식 세션은 Foreground Service가 맡는다. 그래서 다른 앱으로 넘어가도 차량 신호 감시, 음성 안내, 복원이 계속 동작한다. 진행 중에는 알림 한 줄 "휴식 모드 진행 중 · 목표 80%"를 띄운다.
- 백엔드·계정·결제·위치 수집은 없고, 모든 처리는 차량 안에서 끝난다. 앱 자체는 외부로 데이터를 보내지 않는다. 음성 안내 SDK가 서비스 검증 통신을 할 수 있으나, 앱은 차량·개인정보를 넘기지 않는다.
- Pleos 에뮬레이터와 Virtual Console에서 SOC·충전 포트·기어 값을 바꿔 가며 라이브로 시연한다. 에뮬레이터가 시연 장비에서 돌지 않을 때를 대비해, 일반 Android Automotive 에뮬레이터 + 가짜 차량 신호(Fake) 모드로도 같은 플로우를 보여 줄 수 있게 만든다.

**충전 중 판정**: 충전 포트 연결 AND (최근 3분 내 배터리 잔량 상승 OR 충전 스위치 ON). 한 번 판정되면 90초간 유지해 깜빡임을 막고, 포트를 분리하면 즉시 해제한다. 포트 신호를 지원하지 않는 차량만 포트 조건을 생략한다. 기어(`GEAR_PARK`)는 값이 있으면 보조로 쓴다.

**SDK/API 사용 계획**

| 기능 | Pleos SDK / 메서드 | 권한 |
|---|---|---|
| 충전 감지·목표 도달 | Vehicle.EvBattery `registerEvChargePortOpen`, `registerEvBatteryStateOfCharge` / 보조 `getEvChargeSwitchState` | CAR_ENERGY |
| 주행 제한 판정 | AAOS `CarUxRestrictionsManager.isRequiresDistractionOptimization()` / 보조: `Vehicle.getGear()` → `Gear.registerGearSelection` (`VehicleGear.GEAR_PARK` 여부) / 출발 의도: `Brake.registerBrakePedalStatus` | CAR_DRIVE |
| 시트 | Seat `moveSeatBackrestAngle`, `setHvacSeatVentilation`, `getCurrentSeatOccupancy`(리클라인 전 뒷좌석 점검) | CAR_SEATS / CONTROL_CAR_SEATS |
| 조명 | Light 앰비언트 밝기·색·스위치 set(선라이즈: 밝기를 30초 간격으로 값이 바뀔 때만 단계 set, 꺼 둔 조명은 켜지 않음) / 실내등 등 나머지 set | 앰비언트: CAR_LIGHTS / 그 외: CONTROL_CAR_LIGHTS |
| 공조 | HVAC 온도·풍량·외기 유입 set/get(선라이즈: 풍량 1→2단, 충전 중이고 절전 하한이 아닐 때만) | CAR_CLIMATE / CONTROL_CAR_CLIMATE |
| 하차 체크 | Window `getCurrentWindowPosition`, Light 상태, Seat occupancy | CAR_WINDOWS / CAR_LIGHTS / CAR_SEATS |
| 음성 안내 | TextToSpeech(ON_DEVICE 모드, `Locale.KOREA`) `speak` | pleos.car.permission.TTS_SERVICE |

- **차종별 사양 대응**: 시트 등받이와 앰비언트 조명은 시작 시 `check…Capabilities`로 지원 여부와 범위를 한 번 확인한다. 범위 밖 값은 보정하고, 미지원이면 제어하지 않는다. 그 외 항목은 제어를 시도한 뒤 미지원·권한 오류가 돌아오면 그 항목만 건너뛰고 "이 차량 미지원"으로 표시한다. 한계: 충전 스위치 신호가 없는 차량은 출발 시각 모드에서 충전 종료를 SOC 100%로만 감지한다(포트 분리는 그대로 감지).
- **충전 속도 학습 저장**: EvBattery SOC 리스너로 얻은 세션별 기울기(%/분, 2분 이상 데이터)를 지수이동평균(α=0.3)과 관측 횟수로 **기기 로컬 저장소**에만 남긴다. 80% 이하·초과 구간을 따로 저장하고, VIN·계정은 쓰지 않는다. 대기 화면 설정에서 "학습 기록 지우기"로 지운다.
- **상태 복원**: 휴식 모드에 들어가기 직전의 시트·조명·공조를 스냅샷으로 저장한다(메모리 + 로컬 저장소). 앱 프로세스가 다시 시작돼도 스냅샷으로 원래 상태를 되돌린다. 충전 포트를 분리하거나 2시간이 지나면 10초 예고 후 스냅샷으로 복원하고 세션을 종료한다.
- **권한과 사전 협의 계획**
  - Pleos 앱 심사 가이드는 "Vehicle SDK 퍼미션은 Pleos App Market과 사전 협의 및 승인된 경우에만 선언할 수 있습니다"라고 명시한다. 차량 상태를 바꾸는 API에는 별도 심사 기준도 적용된다.
  - 사용 권한은 다음과 같다.
    - 읽기: CAR_ENERGY, CAR_DRIVE, CAR_SEATS, CAR_LIGHTS, CAR_CLIMATE, CAR_WINDOWS, TTS_SERVICE
    - 제어: CONTROL_CAR_SEATS, CONTROL_CAR_LIGHTS, CONTROL_CAR_CLIMATE
  - 차량 충전 설정 제어 권한(CONTROL_CAR_ENERGY)은 요청하지 않는다.
  - 출시 단계에서는 권한별 용도(휴식 씬 진입·복원에 한정)와 주행 제한 중 전면 차단 정책을 첨부해 App Market 사전 협의를 신청한다.
  - 시트 제어가 승인되지 않으면 "권장 자세 안내 + 시트 메모리 호출(`selectSeatMemory`)"로 대체한다.
- **기술 스택**: Kotlin + Jetpack Compose, 단일 Activity + Foreground Service. Pleos 샘플앱과 같은 빌드 도구 버전(AGP 8.8.2, Kotlin 2.0, compileSdk 35)과 Vehicle SDK 2.3.2를 쓴다. 차량 신호 계층을 실제 SDK 구현과 가짜(Fake) 구현으로 나눠, 일반 AVD 개발과 단위 테스트에도 같은 코드를 쓴다.
- **Phase 2 (1차 결과 이후)**: 그랜저·아반떼처럼 EV가 아닌 Pleos 차량을 위한 **수동 휴식 모드**. 충전 신호 대신 타이머를 입력해 같은 휴식·깨움·복원 씬을 실행한다. Pleos 탑재 차량 전체로 설치 대상을 바로 넓힐 수 있다.
